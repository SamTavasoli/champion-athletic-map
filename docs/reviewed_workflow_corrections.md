# Reviewed development workflow

We prepared a new development configuration after reviewing the eighty saved
pilot outcomes. The original code and results remain unchanged.

The candidate selects complete approved basketball variants directly from the
active resource release using public goals and stated resource conflicts.
Selection is conditional evidence, not a feasibility or age-eligibility
certificate. Whole source conditions remain present. Food metadata uses the
existing reversible encoding so the 2200-token packet allowance is unchanged.
The complete request budget still requires its normal separate checks.

The reference-enabled models receive a compact, source-linked view of the
requested nutrient fact alongside the complete original data. They still
generate their own answers. The baseline receives no reference data or lookup
fact. The new audit recognizes copied questions with equivalent quote changes.

The prospective checker separates broken activity accounting from proven
numeric overruns, checks conflict explanations against a limited set of actual
public proofs, and keeps existing-event resources separate from extra-training
supplies. Unknown evidence remains unknown. Literal space aliases are handled
without inferring space adaptations or participant arrangements.

The installation and preparation cell runs offline software checks and replays
the saved public reference rankings for packet-capacity checks. It does not
submit a model request, run the query encoder, change old results, or enable
live app generation. Its diagnostic packets are not substituted for fresh
runtime-bound packets in the next pilot. Backend checks, a small new balanced
development probe, human review and final scoring remain pending.
