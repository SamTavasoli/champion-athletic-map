# Offline revision and food-check corrections

We measured the complete revision requests saved in Step 31-14. The new
candidate revision prompt keeps all athlete facts, complete reference data,
candidate fields, supplied coded findings and evaluator issues unchanged.
Repeated generated specialist notes remain archived with the original system
text in the request configuration instead of being replayed to the reviser.
Concise revision instructions retain the task, scope, uncertainty and source
rules and the existing decoding notices. Model settings, output reserve and
native guards stay unchanged.

The food validator now separates numerical correctness anywhere in the reply
from a complete answer in the required food_facts statement. A correct number
in an explanation cannot fill an incomplete required field. Wrong or
unsupported additional claims prevent a numerical pass. The parser recognizes
a declared narrow grammar; unsupported or ambiguous prose remains unverified.

This step creates prospective candidate files and a separate reassessment of
the saved food replies. It changes none of the original replies or assessments
and sends no requests. Five saved request fits do not establish that every
future request will fit. Backend confirmation and actual revised output quality
remain pending; human ratings and final scoring are not created here.
