# Planner Version 4

We use EvaluatedSpecialistPlanner(root).generate(public_record, reference_packet,
call_id). Each Version 4 job records its own unchanged Version 3 drafting
procedure: training, recovery, optional food and coordinator. Version 3 outputs
are not reused as free drafting work. All roles use the same local Llama model.

We check every candidate with a fixed suite covering output structure, dates,
commitments, relationships/session accounting, durations, availability/collisions,
additional limits, requested session counts, resources, reference identity,
response-type basis, all 29 adopted rule definitions and requested food facts.
Rows distinguish met, violated, unknown and not_applicable, with required or
advisory status fixed before execution. Missing information is not zero or a
pass. Applicability follows public facts and adopted definitions, not the
response type alone. No plan is approved merely because its JSON parses.

Some adopted NBA conditions require complete sports-schedule coverage, which
the current public schema does not attest. Below-limit totals or apparent rest
days can therefore remain required unknowns. Unverified activity requirements,
unrecognized request wording or unverifiable food statements also remain
unknown. Supported non-plan responses follow their own public-input basis.
The implementation does not claim to infer arbitrary free-form meaning or
certify medical safety, youth suitability or real-world effectiveness.

The fixed acceptance policy requires exact nonempty check coverage, a working
checker, resolved applicable required conditions and a completed valid evaluator
assessment without blocking issue categories. Required unknowns and violations
block internal acceptance. Advisory findings remain visible. The evaluator
cannot waive conclusive coded findings or change their required status.

The evaluator receives original public facts, the same complete reference
packet, the current candidate and complete substantive coded findings. It uses
768 output tokens. Revisions receive those original inputs, original complete
specialist notes and current evaluator findings, with 2048 output tokens.
Audit metadata can stay outside prompts; identical findings may be grouped
losslessly and represented as complete rows with shared column names.
No substantive notes, candidate fields, references or qualifications
are truncated or summarized to fit. The complete actual backend-rendered
request is checked before every generation. Overflow is an execution failure.

Candidate 0 is checked and evaluated; a failed acceptance result allows up to
two coordinator revisions, each with fresh full checks and evaluation. We stop
at the first internally accepted candidate, or return the last fully assessed
candidate at the limit with unresolved findings. No best-candidate selection is
made. A required specialist, checker, evaluator or revision execution failure
stops that job; earlier drafts remain diagnostic material, not successful final
outputs. A completed malformed coordinator draft may enter revision. Uncertain
backend outcomes stop the batch. No undeclared retry or evaluator repair runs.

The successful sequence uses four calls without food, five with food when no
revision is needed; its maximum is eight or nine. For these six matched
development profiles the upper bound is 51 new generations. Stable call IDs
reuse saved outputs on reruns, including failed results. Specialist roles do
not restart during revision. No additional query encoding, search, lookup or
classifier prediction is introduced.

We preserve raw candidates and evaluator replies before parsing, all checks,
candidate-parent relationships, issue disagreements, acceptance decisions,
not-started stages, transport counts, token usage, timing and execution errors.
All earlier planners and the exact six saved packets remain unchanged.
Internal review results remain separate from independent research scores.
Accepted final study profiles, independent plan-quality scores and operational
readiness remain unestablished; final evaluation will run separately later.
